# ОрфоДракон — архитектура и объяснение кода

## Общая схема

```
orfodragon/
├── main.py                   ← единственная точка входа Python
├── backend/                  ← серверное ядро (чистый stdlib, 0 зависимостей)
│   ├── config.py             ← константы: пути, порт, версия
│   ├── db/
│   │   ├── connection.py     ← SQLite-соединение, схема БД
│   │   └── kv_store.py       ← обобщённое key-value хранилище
│   ├── domain/
│   │   ├── settings.py       ← настройки приложения и профиль пользователя
│   │   ├── cards.py          ← CRUD карточек + алгоритм SRS (интервальное повторение)
│   │   ├── dictionary.py     ← локальный словарь ударений ФИПИ, поиск
│   │   ├── punctuation.py    ← расстановка запятых по базовым правилам
│   │   ├── gamification.py   ← XP, стрики, босс, миссии, лиги
│   │   ├── ege.py            ← режим пробного экзамена ЕГЭ
│   │   ├── training.py       ← построение тренировочных сессий
│   │   ├── import_export.py  ← импорт/экспорт карточек
│   │   └── state.py          ← снимок всего состояния для фронтенда
│   └── api/
│       └── server.py         ← HTTP-сервер и маршрутизация (GET/POST)
├── electron/
│   ├── main.js               ← главный процесс Electron
│   ├── preload.js            ← скрипт предзагрузки (изолирован)
│   └── package.json          ← зависимости и конфиг electron-builder
├── data/
│   ├── ege_words.json        ← список слов из ФИПИ
│   └── local_dictionary.json ← словарь {слово: «сло́во»}
├── static/
│   └── index.html            ← весь фронтенд (SPA)
└── icons/                    ← иконки приложения
```

## Как работает приложение

### 1. Запуск

`main.py` добавляет корень проекта в `sys.path`, затем вызывает
`backend.api.server.run_server()`. Та:
1. Инициализирует схему БД (`db/connection.py`).
2. Создаёт стартовые карточки из списка ФИПИ, если это первый запуск
   (`domain/import_export.py → initialize_default_cards()`).
3. Находит свободный порт (от 17832), записывает его в файл `port.txt`
   в директории пользовательских данных.
4. Запускает `ThreadingHTTPServer` — каждый запрос обрабатывается в
   отдельном потоке.

### 2. Electron

`electron/main.js`:
1. Гарантирует единственный экземпляр приложения через `requestSingleInstanceLock`.
2. Запускает Python-бинарник (или `python3 main.py` в dev-режиме).
3. Опрашивает порт каждые 250 мс (до 30 секунд), читает `port.txt`.
4. После подъёма бэкенда создаёт `BrowserWindow` и загружает
   `http://127.0.0.1:<port>`.
5. При закрытии приложения убивает дочерний процесс бэкенда.

### 3. База данных (SQLite)

Файл БД хранится в директории пользователя:
- **Windows:** `%APPDATA%\OrfoDragon\orfodragon.db`
- **macOS:**   `~/Library/Application Support/OrfoDragon/orfodragon.db`
- **Linux:**   `~/.local/share/OrfoDragon/orfodragon.db`

**Таблицы:**
- `cards` — карточки (ударения и пунктуация) с параметрами SRS.
- `review_history` — история каждой оценки карточки.
- `settings` — пользовательские настройки (key/value JSON).
- `profile` — игровой профиль (XP, стрики, скины и т.д.).
- `app_state` — флаги состояния приложения.

Все операции записи защищены `threading.Lock` (`db/connection.py →
get_write_lock()`), чтобы не было коллизий между потоками сервера.

### 4. Алгоритм интервального повторения (SRS)

Реализован в `domain/cards.py → grade_card()`.

После каждой оценки карточки пересчитываются три параметра:
- **interval_minutes** — через сколько минут показать снова.
- **ease** — «коэффициент лёгкости» (растёт при правильных ответах,
  падает при ошибках; диапазон 1.3–3.0).
- **reps** — число последовательных правильных ответов.

Логика:
| Ответ    | reps | interval                              | ease       |
|----------|------|---------------------------------------|------------|
| Помню    | +1   | 1-й: second_interval; 2-й: third_interval; далее: `prev × max(1.8, ease)` | +0.15 |
| Забыл    | 0    | `hardResetMinutes / 2`                | −0.25      |

### 5. Словарь и поиск ударений

`domain/dictionary.py`:
1. `get_ege_words()` — загружает `data/ege_words.json` и возвращает
   `frozenset` нормализованных ключей (ё→е). Кэшируется через
   `@lru_cache(maxsize=1)`.
2. `get_dictionary()` — загружает `data/local_dictionary.json`,
   фильтрует только слова из списка ФИПИ, добавляет ручные алиасы
   (слова с «ё», которые ФИПИ пишет без неё). Тоже кэшируется.
3. `search_stress(query)` — ищет в порядке: карточки пользователя →
   словарь → эвристика (первая/последняя гласная).
4. `resolve_stress(word)` — только словарь + эвристика, без БД.

### 6. Геймификация

`domain/gamification.py`:
- **XP и уровень:** XP начисляются за каждый правильный ответ
  и за сдачу ЕГЭ. `level = xp // 100 + 1`.
- **Стрик:** обновляется функцией `touch_daily_activity()` при любой
  активности. Стрик обнуляется, если пользователь пропустил день.
- **Лиги:** каждые 7 уровней — новая лига (Бронзовый → Серебряный → …).
- **Босс:** получает урон после каждого правильного ответа и после
  сдачи ЕГЭ. При победе HP восстанавливается, стадия растёт, открывается
  новый скин.
- **Миссии:** 4 штуки в сутки — ежедневная цель, фокусная тренировка
  (случайная по дате), разогрев, сундук. Прогресс считается по таблице
  `review_history`.
- **Сундук:** открывается раз в сутки после достижения дневной цели;
  с вероятностью 35% даёт новый скин дракона.

### 7. Режим ЕГЭ

`domain/ege.py`:
1. `create_exam()` — случайно выбирает до 5 карточек ударений и 5
   карточек пунктуации, генерирует варианты ответов.
2. Для ударений варианты — все возможные позиции знака ударения.
3. Для пунктуации варианты — правильный вариант + «без запятых» +
   запятые перед разными союзами + позиционные инъекции.
4. `submit_exam(answers)` — проверяет ответы, начисляет XP и урон боссу.

### 8. HTTP API

Все эндпоинты описаны в `api/server.py`. Роутинг — простые `if/elif`
по пути, без сторонних фреймворков.

**GET-эндпоинты:**
| Путь | Описание |
|------|----------|
| `/` | Главная страница (index.html) |
| `/api/state` | Полный снимок состояния |
| `/api/cards` | Список карточек (фильтры: kind, favorite, search, sort) |
| `/api/search?q=слово` | Поиск ударения |
| `/api/due` | Карточки к повторению |
| `/api/ege/session` | Текущая сессия ЕГЭ |
| `/api/export/txt` | Скачать карточки в TXT |

**POST-эндпоинты:**
| Путь | Описание |
|------|----------|
| `/api/cards/grade` | Оценить карточку (remember/forget) |
| `/api/punctuate` | Расставить запятые в тексте |
| `/api/ege/submit` | Сдать экзамен |
| `/api/import/txt` | Импортировать карточки из TXT |
| `/api/chest/claim` | Получить дневной сундук |

## Почему именно такая структура

| Решение | Причина |
|---------|---------|
| Нет внешних Python-зависимостей | Проще сборка PyInstaller, нет конфликтов версий |
| Нет фреймворка (Flask/FastAPI) | Меньше бинарник, нет лишних файлов в дистрибутиве |
| SQLite вместо файлов JSON | Транзакции, конкурентный доступ, индексы |
| `lru_cache` для словарей | Словари большие (~500 слов), загружать при каждом запросе расточительно |
| `threading.Lock` только на запись | Чтение не блокирует параллельные запросы |
| Electron + Python (не Tauri/Go) | Максимальная совместимость с существующим кодом |
